# 대시보드 v2 기능 명세서 (GPT 작업 요청용)

이 문서는 `dashboard.py` / `dashboard.html`을 다음 3가지로 확장하기 위한 명세다.
기존 코드(특히 `decision.py`의 `rank_combinations`, `ocr_extract.py`)는 이미 N개
픽을 다루도록 짜여 있으니 **재사용하고, 새로 만들지 말 것.**

## 1. 캡처를 여러 장 추가 (1폴/2폴/3폴···)

**현재 문제**: 캡처 업로드 칸이 하나뿐이라 경기 하나씩만 넣을 수 있음.

**요구사항**:
- "+ 경기 추가" 버튼으로 캡처 카드를 원하는 만큼 늘릴 수 있어야 한다 (상한 없음,
  다만 6장 넘어가면 "조합 수가 많아져 계산이 느려질 수 있습니다" 경고 표시).
- 각 캡처 카드는 독립적으로: 이미지 업로드 → "이미지에서 배당 추출"(기존
  `/api/ocr-extract` 재사용) → 승/패/언더/오버 후보 버튼 → 클릭해서 픽으로 추가,
  전부 지금 코드에 이미 있는 흐름 그대로다. 카드가 여러 개로 늘어나는 것만 신규.
- 카드마다 "삭제" 버튼으로 제거 가능. 카드를 지우면 그 카드에서 추가된 픽도 같이
  제거.
- 데이터 구조: `captures: [{id, imageData, ocrResult, picks: [...]}]` 배열로
  관리. 기존의 단일 `picks` 배열을 이 구조로 감싸는 형태.

## 2. 추천 버튼 → 3초 딜레이 → 야구공 로딩 애니메이션 → 결과

**요구사항**:
- "추천" 버튼을 누르면 즉시 결과를 보여주지 말고, **최소 3초간** 로딩 화면을 보여준
  뒤 결과를 표시한다. (실제 계산은 서버에서 훨씬 빨리 끝나지만, 사용자가 "계산했다"고
  느끼게 하는 의도적 지연 — `setTimeout`으로 구현, 실제 fetch는 백그라운드에서
  바로 시작해도 되고 3초 후 시작해도 됨. 단, 실제 계산이 3초보다 오래 걸리면
  당연히 그만큼 더 기다림 — 즉 `Promise.all([fetch(...), delay(3000)])`처럼 "3초와
  실제 응답 중 더 늦게 끝나는 쪽"을 기다리는 방식을 권장.)
- 로딩 화면에는 **야구공이 회전하는 애니메이션**을 보여준다. 외부 이미지/라이브러리
  없이 순수 CSS로: 원(⚪) + 빨간 실밥 곡선 2개를 SVG나 CSS로 그리고
  `@keyframes spin { to { transform: rotate(360deg); } }`로 회전.
- 로딩 중 문구는 랜덤하게 하나씩(예: "조합을 계산하는 중...", "배당을 비교하는
  중...", "최적의 픽을 찾는 중...") — 심각한 주제가 아니니 가볍게.

## 3. 추천 결과에 차트/그래프 시각화

**현재 있는 것**: 확률 막대(bar), 확률-기대값 산점도(scatter) — `renderBars`,
`renderScatter` 함수에 이미 구현되어 있음 (SVG 직접 그림, 라이브러리 없음).

**요구사항**: 캡처가 여러 장으로 늘어나 픽 개수가 많아지면, 조합 수(C(n,legs))도
늘어난다. 기존 막대/산점도 로직이 픽 개수 증가에도 깨지지 않는지 확인하고,
다음을 추가:
- 상위 5개 조합을 막대 차트로(기존 `renderBars` 확장 — 이미 top_n=5로 서버가
  잘라주므로 프런트는 그대로 그리면 됨).
- 조합을 구성하는 개별 경기가 어디서 왔는지(어떤 캡처 카드) 툴팁이나 라벨로
  표시하면 좋음 (필수는 아님).

## 재사용할 기존 코드 (새로 만들지 말 것)

| 기능 | 이미 있는 곳 |
|---|---|
| OCR 추출 | `ocr_extract.py`, `/api/ocr-extract` |
| N개 픽 조합 계산, 동일경기 제외, top_n | `decision.py rank_combinations`, `dashboard.py analyze_payload` |
| 막대/산점도 렌더링 | `dashboard.html`의 `renderBars`/`renderScatter` |
| 배당 초안 확인 UI 패턴 | `dashboard.html`의 OCR 결과 버튼 렌더링 부분 |
