## P0: 새 레이아웃 파서가 실제 캡처에서 한 번도 안 켜짐

실제 캡처 3장(`1788309141548`, `1788406671748`, `1788484801823`) 전부
`_layout_market_drafts()`가 아니라 예전 `parse_draft_odds()` 폴백으로
처리됨.

**원인**: `row_count = round((height-57)/71)`가 {5,6,7,8}이어야 새 파서가
작동하는데, 실제 캡처는 다 경기 2개 이상이 한 화면에 찍혀있어서
row_count가 9~11로 나옴. 사용자의 실제 캡처 방식(여러 경기 한 번에)에서는
이 기능이 사실상 죽어있는 상태.

**권장 수정**: 헤더 줄("MLB ... vs ...")을 기준으로 이미지를 여러 경기
블록으로 먼저 나눈 뒤, 각 블록에 지금의 row-crop 로직을 반복 적용하는
방식으로 확장 필요.

## P0: 폴백 파서에서 새 버그 발견 (SUM 행을 승패로 오인)

`1788406671748_image.png`에서 재현됨. 이 캡처는 배당 숫자 소수점이
OCR로 안 잡혀서("2.37"→"2374", "1.41"→"141") `_numbers_on_line()`의
정규식이 앞의 모든 마켓 줄을 건너뛰고, **처음으로 소수점 2개가 잡히는
SUM 행(1.58/2.09)을 승패로 오인식**함. `confidence="ok"`로 표시되어
사용자가 틀린 걸 못 알아챌 위험이 큼.

재현:
```python
from mlb_decision_model.ocr_extract import extract_odds
with open("1788406671748_image.png", "rb") as f:
    drafts = extract_odds(f.read())
# 실제: 승2.37/패1.40   결과: 승=1.58/패=2.09 (SUM 값을 승패로 오인, confidence=ok)
```

**권장 수정**: "숫자 2개 있는 첫 줄"이 아니라, "야구 승패" 헤더 자체를
먼저 찾고 그 헤더에 대응하는 행의 숫자만 신뢰하도록 앵커링 방식 변경.
또는 최소한 소수점 없는 숫자가 몰린 줄이 나오면 confidence를 partial로
낮춰서 사용자에게 확인을 유도.
